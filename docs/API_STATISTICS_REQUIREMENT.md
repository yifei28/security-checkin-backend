# API统计功能需求文档

## 问题描述

当前签到记录页面的统计功能存在以下问题：

1. **统计数据不完整**：统计数据（成功/失败/待处理数量）只计算当前页面的20条记录，而不是所有符合筛选条件的记录。
2. **日期筛选问题**：当选择"今天"作为时间筛选条件时，仍会显示其他日期的记录。

## 解决方案

### 方案一：在分页响应中包含统计数据（推荐）

修改现有的 `GET /api/checkin` 接口，在响应中添加 `statistics` 字段：

```json
{
  "success": true,
  "data": [...], // 当前页的记录
  "pagination": {
    "total": 100,
    "page": 1,
    "pageSize": 20,
    "totalPages": 5
  },
  "statistics": {
    "totalRecords": 100,      // 符合筛选条件的总记录数
    "successCount": 75,       // 成功签到总数
    "failedCount": 20,        // 失败签到总数
    "pendingCount": 5,        // 待处理签到总数
    "successRate": 75         // 成功率百分比
  }
}
```

**实现细节：**
- 统计数据应该基于所有符合当前筛选条件的记录，而不仅仅是当前页
- 筛选条件包括：日期范围、保安ID、站点ID、状态

### 方案二：创建独立的统计接口

创建新的统计接口 `GET /api/checkin/statistics`：

**请求参数：**
- `startDate` (可选): 开始日期，格式：`YYYY-MM-DDTHH:mm:ss`
- `endDate` (可选): 结束日期，格式：`YYYY-MM-DDTHH:mm:ss`
- `guardId` (可选): 保安ID
- `siteId` (可选): 站点ID
- `status` (可选): 状态筛选 (success/failed/pending)

**响应格式：**
```json
{
  "success": true,
  "data": {
    "totalRecords": 100,
    "successCount": 75,
    "failedCount": 20,
    "pendingCount": 5,
    "successRate": 75
  }
}
```

## 日期筛选问题修复

### 时间格式要求

前端发送的时间参数格式：
- 格式：`YYYY-MM-DDTHH:mm:ss`（北京时间，无时区后缀）
- 示例：`2025-01-15T00:00:00` 到 `2025-01-15T23:59:59`

### 后端处理要求

1. **正确解析时间参数**：
    - 将接收到的时间字符串作为北京时间处理
    - 不要进行时区转换

2. **筛选逻辑**：
    - 使用 `timestamp >= startDate AND timestamp < endDate` 进行筛选
    - 确保比较的是同一时区的时间

## 前端已实现的部分

前端已经实现了以下功能：

1. **统计数据展示优化**：
    - 检测后端是否返回 `statistics` 字段
    - 如果有，使用完整的统计数据
    - 如果没有，显示当前页统计并标注"(本页)"提示

2. **API客户端支持**：
    - 已创建 `getCheckInStatistics` 方法用于调用独立统计接口
    - 支持所有筛选参数

3. **时间格式处理**：
    - 正确格式化本地时间为 `YYYY-MM-DDTHH:mm:ss` 格式
    - 不添加时区后缀

## 测试场景

1. **统计数据测试**：
    - 选择"今天"筛选，验证统计数据是否包含今天所有记录
    - 选择特定保安，验证统计数据是否为该保安的所有记录
    - 分页切换时，统计数据应保持不变

2. **日期筛选测试**：
    - 选择"今天"，应只显示今天的记录
    - 选择"本周"，应显示最近7天的记录
    - 选择"本月"，应显示最近30天的记录

## 实现优先级

1. **高优先级**：修复日期筛选问题
2. **中优先级**：在现有接口响应中添加统计数据（方案一）
3. **低优先级**：创建独立的统计接口（方案二，作为备选）
